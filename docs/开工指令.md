# 开工指令

> 开新对话时把下面代码块里的内容整段复制过去即可。

```
在 D:\pictureMore 开始开发「图压压 pictureMore」。所有设计、规范、实施计划都已定稿在仓库里。

第一步：读 AGENTS.md。它是入口页，会告诉你读文档的顺序、第一件事做什么、三条不能破的线，以及一张硬性约束速查表。然后读 SPEC.md 和 docs/superpowers/plans/2026-09-19-picturemore-v1.md。

第二步：用 executing-plans 技能，从实施计划的 Task 0 开始，一个 Task 一个 Task 往下做。每个 Task 结束跑 npm run check。

三条硬要求：

1. Task 0（M0 技术验证）必须真跑，不要跳过去先搭项目。它验证的是 sharp 能不能解 HEIC、以及 metadata API 的确切行为，两者都可能推翻文档里的假设。跑完把结论写进 docs/decisions.md 再往下走。
2. 不要引入 SPEC.md §15 之外的任何依赖。v1 的运行时依赖只有 sharp、heic-decode、zustand 三个。特别地：不用 nanoid（用 crypto.randomUUID()）、不用 electron-store、不用 react-router-dom、不装图标库。
3. 视觉以 prototype/index.html 为唯一基准。写界面时把它在浏览器打开，和实现并排比对。文案只能取自 SPEC.md §8.4 文案表，不要自造词。界面零图标、零 emoji、零 em-dash。

遇到不确定时：先查 SPEC.md §14 已知陷阱，再查 README.md 的红线清单，都不覆盖就停下来问我，不要猜。

除了真正卡住的情况，不要中途停下来征求我的意见，按计划推进。每完成一个 Task 简短汇报一次。
```

---

## 复制之前，你自己先做一件事

Task 0 需要一张**真实的 iPhone HEIC**，sharp 编不出来，也没法从网上拉。

1. 从 iPhone 导出两张原始 HEIC（用 AirDrop 或数据线，**不要用微信转发**，会被转成 JPG）
2. 放到 `D:\pictureMore\tests\fixtures\`，命名为：
   - `iphone-portrait.heic`（竖拍）
   - `iphone-landscape.heic`（横拍）

没有这两张的话，Task 0 的 HEIC 兜底部分和后续的 HEIC 测试会 skip，但其余流程仍能跑通。**建议还是准备一下**，HEIC 是这个产品的核心输入格式。
